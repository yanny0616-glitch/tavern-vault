# TavernVault 酒馆藏馆

一个独立运行的 SillyTavern / TauriTavern 资源仓库：角色卡、世界书、预设、正则、脚本、快速回复、主题、背景、聊天记录、提示词……都能收进来。

- **不开酒馆也能用**：手机 Safari、电脑浏览器直接访问，上传、浏览、编辑都可以。可以添加到 iPhone 主屏幕当 App 用。
- **在酒馆里也能用**：装上插件后，SillyTavern 和 TauriTavern 里都能全屏打开同一个仓库（铺满整个屏幕，只给灵动岛 / 状态栏和底部 Home 条留出位置，关闭按钮在右上角）。在酒馆里打开时，还能把酒馆已有的内容一键收进仓库，或者把仓库内容一键导入酒馆。
- **实时互通**：所有入口连的是同一个服务，一边修改，另一边马上刷新。

```
             ┌──────────────────────────────┐
             │   藏馆服务（Node.js，零依赖）  │  ← 唯一数据源
             │   db.json + 去重文件仓库 + 网页 │
             └───────┬──────────────┬───────┘
                     │ HTTPS (Cloudflare Tunnel)
      ┌──────────────┘              └──────────────┐
 iPhone Safari / 电脑浏览器                 SillyTavern / TauriTavern
 直接访问网页                              插件全屏内嵌同一网页
                                          + postMessage 桥读写酒馆本地数据
```

## 一、部署服务端（云服务器 + Cloudflare）

### 1. 运行

```bash
cd tavern-vault/server
TV_HOST=127.0.0.1 TV_PORT=5180 TV_PASSWORD='设置一个强密码' node server.js
```

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `TV_PORT` | `5180` | 端口 |
| `TV_HOST` | `0.0.0.0` | 用 Cloudflare Tunnel 时**请设为 `127.0.0.1`**，不要直接暴露端口 |
| `TV_DATA` | `server/data` | 数据目录 |
| `TV_PASSWORD` | 无 | 首次启动时设置的访问密码，之后可在网页「设置」里修改 |
| `TV_MAX_UPLOAD_MB` | `200` | 单个文件上传上限 |
| `TV_MAX_RESTORE_MB` | `2048` | 从备份还原时备份文件的大小上限 |

开机自启：

```bash
sudo cp deploy/tavern-vault.service /etc/systemd/system/
# 按需修改里面的路径和密码
sudo systemctl daemon-reload && sudo systemctl enable --now tavern-vault
```

### 2. 用 Cloudflare Tunnel 绑定域名（推荐）

好处：不用开放端口，自动 HTTPS。iOS 上 TauriTavern 内嵌页面必须用 HTTPS。

**控制台方式（最简单）：**

1. Cloudflare 控制台 → Zero Trust → Networks → Tunnels → Create a tunnel → Cloudflared
2. 复制页面上给出的安装命令，在服务器上执行（`cloudflared service install <token>`）
3. Public Hostname 添加一条：子域名 `vault`，域名选你的，Service 填 `HTTP` + `127.0.0.1:5180`
4. 打开 `https://vault.你的域名`

**命令行方式：** 参考 `deploy/cloudflared-config.example.yml`。

> 注意：Cloudflare 免费套餐单个请求上限 100MB，超过的文件请直接在服务器本机上传。

> 前面如果还有 Nginx / Caddy 等反向代理，不要强制覆盖 `Cache-Control`。程序已经给每类响应设好了缓存策略：数据接口不缓存，封面和带版本号的脚本长期缓存，并且都是 `private`，Cloudflare 不会缓存，也不会改写。

### 3. 第一次打开

- 如果没有用 `TV_PASSWORD` 启动，请立刻到「设置 → 访问密码」设置密码。在这之前，任何知道网址的人都能访问。
- iPhone：Safari 打开 → 分享 → 「添加到主屏幕」。

## 二、安装酒馆插件

插件目录是 `extension/`，SillyTavern 和 TauriTavern 共用一份。

### TauriTavern（iOS / Android / 桌面）

在 TauriTavern 中：扩展 → 安装扩展 → 填入主仓库地址

```
https://github.com/yanny0616-glitch/tavern-vault
```

主仓库根目录的 `manifest.json` 指向 `extension/index.js`，所以可以直接安装。如果只想装插件、不下载服务端代码，也可以用只含插件的仓库 `https://github.com/yanny0616-glitch/tavern-vault-extension`，两个地址装出来是同一个插件。

> **iOS 注意**：公开 TestFlight 包（`ios_external_beta` 配置）默认禁用第三方扩展。自签 IPA 或 Stable/Canary 包默认允许。

### SillyTavern

扩展 → 安装扩展，填同一个地址；也可以在藏馆「设置」页下载插件压缩包，解压到 `SillyTavern/data/default-user/extensions/tavern-vault/`。

### 配置

扩展设置 →「TavernVault 酒馆藏馆」→ 填写服务器地址（如 `https://vault.example.com`）和密码 → 点「连接」。

打开方式：左下角魔棒菜单 →「酒馆藏馆」，或者点可拖动的悬浮按钮。

在酒馆里打开时，底部会多出「酒馆」页：

- **酒馆 → 仓库**：浏览酒馆里的角色卡、世界书、预设、正则、快速回复、主题、背景，可以单个或批量收藏进仓库，角色卡导出为完整 PNG。已收藏的条目会自动比对内容，标出：
  - **已同步**：两边内容一致
  - **酒馆有改动**：在酒馆里改过，可以「对比」或「存为新版本」
  - **藏馆较新**：酒馆里还是旧版本，可以「更新到酒馆」（原地覆盖）
  - **版本不同**：酒馆里是藏馆的另一个历史版本
- **仓库 → 酒馆**：在任意条目详情里点「导入到酒馆」，或多选后批量导入。酒馆里已有同名时会询问「覆盖 / 另存一份 / 跳过」；内容完全一致的自动跳过。覆盖角色卡会保留它在酒馆里的聊天记录。角色卡和世界书会立即刷新；预设、正则、主题、快速回复需要刷新酒馆页面后才能在列表里看到。

比对和覆盖需要插件 1.1.0 及以上。已经装过旧版的，在酒馆的扩展管理里点更新即可；旧版插件仍能用，但页面上会提示更新。

## 三、iOS 快捷指令：分享即上传

在「设置 → iPhone 小技巧」里有地址和访问令牌：

1. 新建快捷指令，打开「在共享表单中显示」，接收类型选「文件」「图像」
2. 添加「获取 URL 内容」：URL 填 `https://vault.你的域名/api/items?filename=快捷指令上传`，方法选 POST，请求体选「文件」并选择「快捷指令输入」
3. 如果设置了密码，在头部添加 `Authorization`，值为 `Bearer <令牌>`
4. 之后在 Safari、Discord、「文件」等 App 里分享角色卡，选这个快捷指令即可

## 四、AI 功能

在「设置 → AI 助手」添加服务：

- 支持 **OpenAI 兼容接口**（各类中转、DeepSeek、本地模型等）和 **Claude 官方接口**，可以存多个，随时切换
- 密钥保存在服务器的 `data/ai.json`（权限 600），网页和酒馆插件都拿不到，也不会进备份；请求由服务器发出，手机上不会遇到跨域问题
- 「整理规则」里可以设置读取范围（精简 / 标准 / 完整）、标签数量、简介字数、是否允许新建标签、让 AI 填写哪些字段，以及你自己的整理习惯
- 开始前会显示预计 token 用量，也可以先看完整的发送内容
- 卡片内容会作为数据交给 AI，并明确要求忽略其中的任何指令；AI 的返回会校验格式，字段只接受允许的值

使用：在仓库里多选条目点「AI 整理」，或在条目详情里点「AI 整理」。右下角会显示进度和待审核数量。筛选里可以只看「未整理」的条目。

## 五、数据与备份

- 数据都在 `server/data/`：`db.json` 是索引，`files/` 存按 SHA-256 命名的原始文件
- 「设置 → 下载完整备份」得到包含所有版本文件的 ZIP；在「设置 → 从备份还原」上传即可恢复，可以选「合并」（保留现有内容）或「替换」。也可以直接把 ZIP 解压回 data 目录
- 每次还原前会把当前数据库存一份到 `data/restore-points/`（保留最近 10 份）
- 自动备份默认开启：每天在 `data/backups/` 存一份完整备份（内容没变的日子不重复存），保留最近 7 份，可改为 3 / 14 / 30 份；也可以随时「立即备份」，在设置里下载、还原或删除。备份和数据在同一台服务器上，建议偶尔下载一份到自己的设备
- 删除的内容先进回收站，永久删除后会自动清理没有被引用的文件

## API 一览

除 `/api/health`、`/api/login`、`/api/extension.zip` 外，其余接口在设置密码后需要带 `Authorization: Bearer <token>`（或 `?token=`）。

| 方法 | 路径 | 说明 |

| GET | `/api/events` | SSE 实时事件 |
| POST | `/api/items?filename=&type=&tags=&collections=&match=&target=&zipCollection=&collectionName=` | 上传文件（原始 body），自动识别；ZIP 自动解压。返回 `status`：`created` / `version` / `duplicate` / `conflict` / `skipped` |
| POST | `/api/ingest/resolve` | 处理同名冲突：`{sha, filename, action: version\|new\|skip, target}` |
| POST | `/api/diff` | 对比两个文件：`{a: {sha, name}, b: {sha, name}}` |
| POST | `/api/import-url` | `{url}` 由服务器下载 |
| POST | `/api/items/manual` | 新建无文件条目 |
| POST | `/api/items/merge` | 合并重复条目：`{target, sources, newest}` |
| GET/PATCH/DELETE | `/api/items/:id` | 读取 / 修改 / 删除（`?hard=1` 永久删除） |
| GET | `/api/items/:id/content` | 主文件解析后的内容 |
| PUT | `/api/items/:id/card` | 保存编辑后的角色卡（生成新版本） |
| GET | `/api/search?q=` | 按文件内容全文搜索，返回命中的条目和片段 |
| POST/PATCH/DELETE | `/api/items/:id/files[/:fid]` | 版本与附件管理 |
| POST | `/api/batch` | 批量操作 |
| POST | `/api/export` | `{ids}` 导出 ZIP |
| GET | `/api/backup` | 完整备份 |
| GET/POST | `/api/backups` | 服务器上的备份列表 / 立即备份 |
| GET/DELETE | `/api/backups/:name` | 下载 / 删除一份服务器备份 |
| POST | `/api/backups/:name/restore?mode=merge\|replace` | 从服务器上的备份还原 |
| POST | `/api/backups/ack` | 确认条目是自己删的：按现在的数据存一份备份，恢复自动备份 |
| GET | `/api/security/log` | 最近的登录记录和正在暂停的来源 |
| GET/PUT/DELETE | `/api/thumbs[/:sha]` | 封面缩略图：读取 / 上传（浏览器生成）/ 全部删除后重建 |
| GET | `/api/storage` | 文件、缩略图、数据库占用空间 |
| GET/PUT | `/api/ai/config` | AI 服务与整理规则（密钥只写不读） |
| POST | `/api/ai/test`、`/api/ai/models` | 测试连接、拉取模型列表 |
| POST | `/api/ai/organize`（及 `/estimate`、`/preview`） | 加入整理队列 / 估算用量 / 预览发送内容 |
| GET / POST | `/api/ai/drafts`、`/api/ai/drafts/apply`、`/api/ai/drafts/discard`、`/api/ai/cancel` | 审核草稿 |
| POST | `/api/ai/explain` | AI 解读两个版本的差异：`{a, b, aLabel, bLabel}` |
| POST | `/api/restore?mode=merge\|replace` | 从备份 ZIP 还原（还原前自动保存当前数据库到 `data/restore-points`） |
| GET | `/api/files/:sha` | 下载文件 |
